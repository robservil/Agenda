# Versioning Policy

El proyecto utiliza **Semantic Versioning**.

Formato:

MAJOR.MINOR.PATCH

Ejemplo:

1.2.3

## MAJOR

Cambios incompatibles con versiones anteriores, rotura de contrato de API o cambios destructivos en BD.

## MINOR

Nuevas funcionalidades compatibles, nuevos endpoints o tablas de BD

## PATCH

Correcciones de bugs compatibles.

## Ejemplos

1.0.0 → primera versión estable  
1.1.0 → nueva funcionalidad  
1.1.1 → bug fix
